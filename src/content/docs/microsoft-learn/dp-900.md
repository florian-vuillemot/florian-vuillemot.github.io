## Data format

- **Structured**: Data that adheres to a strict schema, making it easily searchable and analyzable. Examples include:
   - **[SQL](https://en.wikipedia.org/wiki/SQL)**: Structured Query Language, used for managing and manipulating relational databases.
   - **[Excel files](https://en.wikipedia.org/wiki/Microsoft_Excel)**: Spreadsheet files that organize data in rows and columns, often used for data analysis and visualization.
- **Semi-structured**: Data that does not conform to a rigid schema but still contains tags or markers to separate data elements. Examples include:
   - **[Avro](https://avro.apache.org/)**: A row-oriented remote procedure call and data serialization framework developed within Apache's Hadoop project.
   - **[CSV](https://en.wikipedia.org/wiki/Comma-separated_values)**: Comma-separated values, often used for tabular data.
   - **[JSON](https://www.json.org/)**: JavaScript Object Notation, commonly used for transmitting data in web applications.
   - **[ORC](https://orc.apache.org/)**: Optimized Row Columnar format, used for efficient storage and querying in Hadoop.
   - **[Parquet](https://parquet.apache.org/)**: Columnar storage file format optimized for use with big data processing frameworks.
   - **[XML](https://en.wikipedia.org/wiki/XML)**: Extensible Markup Language, used to encode documents in a format that is both human-readable and machine-readable.
- **Unstructured**: Data that lacks a predefined format or organization, making it more challenging to collect, process, and analyze. Examples include:
   - **[Video](https://en.wikipedia.org/wiki/Video)**: Multimedia files that contain moving visual media.
   - **[Audio](https://en.wikipedia.org/wiki/Audio_file_format)**: Files that contain sound recordings.

## OLAP and OLTP

- **OLAP (Online Analytical Processing)**: Used for complex queries and data analysis, often involving large volumes of data. It is optimized for read-heavy operations and supports multidimensional data analysis. Examples include:
   - **Data Warehouses**: Central repositories of integrated data from multiple sources, optimized for querying and reporting.
   - **Business Intelligence Tools**: Software applications used to analyze an organization's raw data.
- **OLTP (Online Transaction Processing)**: Used for managing transaction-oriented applications. It is optimized for a large number of short online transactions (insert, update, delete). Examples include:
   - **Relational Databases**: Databases that store data in tables with rows and columns, supporting transactional operations.
   - **ERP Systems**: Enterprise Resource Planning systems that manage business processes in real-time.

## SQL

Basic knowledge in SQL is necessary for the certification. Moreover, the user must know how commands are categorized into different types based on their functionality. The three main categories are:

- **DML (Data Manipulation Language)**: These commands are used to manipulate the data stored in the database. Examples include:
   - **INSERT**: Adds new records to a table.
   - **UPDATE**: Modifies existing records in a table.
   - **DELETE**: Removes records from a table.
   - **SELECT**: Retrieves data from one or more tables.

- **DDL (Data Definition Language)**: These commands are used to define and manage database schema. Examples include:
   - **CREATE**: Creates a new table, view, or other database object.
   - **ALTER**: Modifies an existing database object, such as adding a column to a table.
   - **DROP**: Deletes an existing database object.
   - **TRUNCATE**: Removes all records from a table, but keeps the table structure.

- **DCL (Data Control Language)**: These commands are used to control access to data in the database. Examples include:
   - **GRANT**: Gives a user permission to perform specific actions on database objects.
   - **REVOKE**: Removes a user's permissions.

## Data Organization

Understanding how data is organized is crucial, and questions based on use cases can be asked. Here are some key concepts:

- **Data Warehouse**: Relational data stores where the schema is optimized for analytics. They are denormalized for faster and simpler queries, often using star and snowflake schemas. These schemas consist of a central fact table and surrounding dimension tables (with hierarchies in the snowflake schema).
- **Data Lakes**: Storage systems used for high-performance access to structured, semi-structured, and unstructured data, or a mix of all three. They use a schema-on-read approach.
- **Data Lakehouses**: Hybrid systems that combine the features of data warehouses and data lakes. They store all types of data and support SQL queries.

## Database Normalization

Database normalization is a process used to organize a database into tables and columns. The main goals of normalization are to reduce data redundancy and improve data integrity. Here are some key benefits:

- **Less Data to Store**: By eliminating redundant data, normalization reduces the amount of data that needs to be stored.
- **Improved Data Integrity**: Normalization ensures that data is logically stored, which helps maintain data accuracy and consistency.

Normalization typically involves dividing large tables into smaller, related tables and defining relationships between them. This process is guided by a series of rules known as normal forms, each addressing specific types of redundancy and dependency issues.

## ETL and ELT

### ETL (Extract, Transform, Load)

ETL is a process used in data warehousing and data integration that involves extracting data from various sources, transforming it into a suitable format, and then loading it into a target database or data warehouse. 

- **Extract**: Data is extracted from different source systems.
- **Transform**: The extracted data is transformed into a format that can be analyzed. This may include cleaning, aggregating, and enriching the data.
- **Load**: The transformed data is loaded into the target system, such as a data warehouse.

**Advantages of ETL**:
- **Data Quality**: Ensures that data is cleaned and transformed before loading, improving data quality.
- **Consistency**: Provides a consistent process for data integration.
- **Complex Transformations**: Supports complex data transformations before loading into the target system.

### ELT (Extract, Load, Transform)

ELT is a variation of the ETL process where data is first extracted and loaded into the target system, and then transformed as needed. This approach is often used with modern data lakes and cloud-based data warehouses.

- **Extract**: Data is extracted from various source systems.
- **Load**: The extracted data is loaded into the target system in its raw form.
- **Transform**: The loaded data is transformed within the target system.

**Advantages of ELT**:
- **Scalability**: Leverages the scalability of modern data warehouses and cloud platforms.
- **Flexibility**: Allows for more flexible and on-demand data transformations.
- **Performance**: Can take advantage of the processing power of the target system for transformations.

For more detailed information, you can refer to the following resources:
- [Azure Data Factory](https://learn.microsoft.com/en-us/azure/data-factory/introduction)
- [ETL vs ELT](https://learn.microsoft.com/en-us/azure/architecture/data-guide/relational-data/etl)

## Azure Storage

Azure Storage offers a variety of services to store and manage data in the cloud.
These services include Azure Blob Storage, Azure Data Lake Storage, Azure Files, and Azure Queue Storage, among others.
Each service is designed to handle different types of data and use cases, providing scalable, durable, and secure storage solutions.

- **Azure Blob Storage**: Ideal for storing unstructured data such as text, binary data, images, and videos. It is highly scalable and can handle large amounts of data.
- **Azure Data Lake Storage**: Optimized for big data analytics, it combines the scalability and cost benefits of object storage with the reliability and performance of the Hadoop Distributed File System (HDFS).
- **Azure Files**: Provides fully managed file shares in the cloud that are accessible via the Server Message Block (SMB) protocol. It is useful for lifting and shifting applications to the cloud that rely on file shares.
- **Azure Queue Storage**: Designed for storing large numbers of messages that can be accessed from anywhere via authenticated calls using HTTP or HTTPS.
- **Azure Table Storage**: A NoSQL key-value store for rapid development using massive semi-structured datasets. It is ideal for applications that need a flexible data schema and require high availability and scalability.

Note: Azure File Sync is a service that allows you to centralize your file shares in Azure Files while keeping the flexibility, performance, and compatibility of an on-premises file server. It helps reduce latency for on-premises users by caching frequently accessed files locally. This service is particularly useful for organizations looking to extend their on-premises file servers to the cloud without sacrificing performance. [Learn more](https://learn.microsoft.com/en-us/azure/storage/file-sync/file-sync-introduction).

## Cosmos DB

Azure Cosmos DB is a globally distributed, multi-model database service designed to provide high availability, low latency, and scalability.
It supports multiple APIs, including SQL, MongoDB, Cassandra, Gremlin, and Table, allowing developers to use their preferred data models and query languages.
Cosmos DB ensures seamless data replication across multiple regions, making it ideal for mission-critical applications that require real-time data access and consistency.
Knowing each API and their advantages is necessary.
